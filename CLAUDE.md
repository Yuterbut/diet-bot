# diet-bot

Telegram-бот: недельный план питания под бюджет + ИИ-диетолог с дневником КБЖУ.
Python 3 / Flask, вебхук Telegram, деплой на PythonAnywhere.

## Запуск и проверка

```bash
python3 -m pytest -q          # тесты, сеть в них заблокирована
python3 -m py_compile *.py    # быстрая проверка синтаксиса
```

Секреты — в переменных окружения (`.env` не в репозитории): `TELEGRAM_BOT_TOKEN`,
`GROQ_API_KEY`, `OPENAI_API_KEY`, `GITHUB_MODELS_TOKEN`, `CRON_SECRET`, `GITHUB_SECRET`,
`ADMIN_CHAT_ID`, `PA_API_TOKEN`/`PA_USERNAME`/`PA_DOMAIN`.

Деплой автоматический: пуш в `main` → GitHub-вебхук → `git pull` на сервере →
релоад веб-аппа через API PythonAnywhere. Без релоада воркер продолжит работать
на старом коде, даже если файлы обновились.

## Модули

| Файл | Назначение |
|---|---|
| `flask_app.py` | все HTTP-роуты, вся логика Telegram: клавиатуры, колбэки, состояния диалога |
| `planner.py` | подбор недельного меню, список покупок, стоимость, замена блюд |
| `meals_data.py` | база из 243 блюд, **сгенерирована** `scripts/generate_meals.py` — правится генератором, не руками |
| `products.py` | 225 продуктов: цены, фасовка, категория |
| `nutrition_data.py` | таблица `NUTRI` (КБЖУ на 100 г) и детерминированный расчёт макросов |
| `ai_agent.py` | обёртка над ИИ: оценка еды, генерация блюд, чат диетолога |
| `food_lookup.py` | КБЖУ по тексту: сначала Open Food Facts, потом ИИ |
| `nutrition.py` | формулы BMR/TDEE и суточных норм |
| `storage.py` | хранилище пользователей в JSON-файле |

## Что стоит знать до правок

**У блюд уже есть `difficulty` (`easy`/`medium`) и `time` в минутах**, у продуктов —
`category`. Фильтрация по навыку готовки и списку продуктов строится на этих полях,
новых заводить не нужно.

**План хранится только как список названий** (`plan_names`). Название превращается
обратно в блюдо через `MEAL_INDEX` — статический индекс, собранный при импорте.
Поэтому у блюда, придуманного ИИ, в индексе записи нет: такие блюда живут в
`user["custom_meals"]` и передаются в `planner` параметром `custom=`. Забыть его —
значит получить блюдо без рецепта и с нулевым КБЖУ в дневной сумме.

**ИИ никогда не называет калории.** `ai_agent.generate_meal` просит у модели только
ключи продуктов и граммы, КБЖУ считается локально по `NUTRI`. Ответ, не прошедший
проверку, отбрасывается целиком. Так калорийность не может быть выдумана.

**В `NUTRI` значения для ключей из `PER_PIECE_KEYS` (`eggs`, `eggs_quail`, `avocado`)
даны на штуку, а не на 100 г.** Легко не заметить и посчитать яйцо как 100 граммов.

**Запись в `storage.py` требует блокировки.** Цикл «прочитать — изменить — записать»
без `_locked()` теряет данные: воркеров несколько, запись из вебхука накладывается на
запись из крона. Любая новая функция, меняющая файл, должна брать блокировку.

**Функции из `ai_agent.py` не бросают исключений** — при сбое возвращают `None`.
Бот обязан работать, когда ИИ недоступен. Этот контракт нарушать нельзя.

**Ограничения по здоровью важнее вкусовых.** Если под фильтры не нашлось блюд,
`candidates()` снимает их по очереди — сначала уровень готовки и список продуктов,
и только в последнюю очередь цель. Аллергии и вегетарианство не снимаются.

## Договорённости по стилю

- Комментарии и строки для пользователя — **по-русски**.
- Комментарий объясняет **почему**, а не что делает код. Хорошие образцы —
  `_pack_price` и `_marginal_cost` в `planner.py`.
- Docstring, пересказывающий очевидное, не нужен.
- В тестах сеть заблокирована автофикстурой в `tests/conftest.py`: внешние вызовы
  мокаются, реальных запросов быть не должно.
